# 科学解析

muscat-db は複数の望遠鏡による多色トランジット観測を扱います。FITS 画像から光度曲線を作り、惑星・恒星のパラメーターやトランジット時刻変動（TTV）を推定します。比較星を含む視野の選定、露出時間の見積もり、カタログの照合、観測計画も同じ天体のデータを使って行えます。

## 解析手法と入力データ

| 手法 | 処理 |
|---|---|
| prose2 による差分測光 | gp、rp、ip、zs、狭帯域などにフレームを分け、位置や品質（FWHM、エアマスなど）から基準画像を選びます。点源を検出し、WCS と MAST/SIMBAD の座標で天体を同定します。Gaia DR3 の近傍星を考慮して開口と背景環を設定し、画像の切り出し、ガウスモデル、Twirl による位置合わせ、重心調整、フラックス抽出を並列処理します。Broeg et al. (2005) に基づき、MAD などの頑健な尺度で比較星を反復選択・重み付けします。時刻は astropy.time または barycorrpy で JD-UTC から BJD-TDB に変換します。 |
| timer によるトランジットフィット | カタログ値や手入力値（有効温度、表面重力、金属量、周期、基準時刻、継続時間、インパクトパラメーターなど）を使います。各バンドのトランジット光度曲線を `exoplanet.LimbDarkLightCurve` で計算し、露出時間を考慮します。二次の周縁減光則の係数はバンドごとに 2 個あり、固定またはサンプリングできます。系統誤差は線形モデルまたはガウス過程で扱います。L-BFGS による MAP 最適化で初期化し、PyMC の NUTS で事後分布をサンプリングします。 |
| harmonic による TTV フィット | O−C（観測時刻と計算時刻の差）から得た中心時刻、誤差、エポックを使用します。Lithwick, Xie & Wu (2012) の共鳴近傍のモデルを用い、emcee で事後分布を推定します。config.ini に振幅、超周期、位相の基準、トランジットしない外側惑星や位相ずれの設定を記述します。 |
| 視野の最適化 | 東西・南北の指向オフセットと位置角を格子探索し、視野に入る比較星を評価します。Gaia DR3 の等級差、色の類似度、近接星による混入、観測所の緯度や高度制約を用います。 |
| 露出計算 | 装置・バンド・焦点別の経験較正から露出時間と S/N の関係を求め、検出器のフルウェル容量から飽和の可能性を調べます。[露出計算と等級の取得](exposure.md)に計算条件があります。 |

測光の主入力は生または較正済み FITS 画像です。CSV 観測ログの天体名、装置、日付、フィルター、座標、露出時間を索引やジョブの選択に使います。NASA Exoplanet Archive と TOI は暦表・恒星・惑星パラメーターを、LCO Observation Portal は観測窓の予約、IPP の検証、アーカイブ取得情報を提供します。WCS のない MuSCAT/MuSCAT2 には nova.astrometry.net による座標解決も利用できます。時系列解析では太陽系重心への時刻補正や周期解析を扱います。

## 測光に使う座標

測光画面で入力した座標が最優先です。未指定ならオフラインの NASA/TOI カタログで、まず主星名、次に FITS の OBJECT（例：DS Tuc、次に DS Tuc b）を検索します。外部の名前解決は表記違いを含めて合計 3 秒まで待ち、成功だけをキャッシュします。通信失敗と未知の天体を区別できないためです。

同一天体への同時リクエストは 1 回の検索を共有します。外部検索はプロセスごとに最大 4 ワーカーで、待ち行列は作りません。開始済みの通信が期限後に完了しても追加検索は停止し、時間内に座標を得られなければ元の OBJECT を prose に渡します。ログには実際に渡した情報を残します。外部サービスに依存せずに実行するには座標を入力してください。

## 測光精度の設定

**Precision** は prose2 v3.8.0 の比較星処理を設定します。既定は比較星を順次選ぶ方式で、天体の散らばりを基準にし、星ごとのクリッピングは行いません。設定はデータセットごとに保存され、**Use default settings** で戻せます。

- **All bright, consistent comparisons** は比較星/天体フラックス比（既定の下限 0.3）を満たし、互いに整合する比較星をフラックスで重み付けします。ID を明示するとその選択が優先されます。
- **Comparison check light curves** は、比較星と天体の誤差モデルから比較星数と開口を選びます。天体のトランジットを含む光度曲線を最適化の指標にしません。
- **Comparison-star clipping** は差分を取る前に比較星の外れ値を移動中央値（既定 11 フレーム）で判定し補間します。空欄で無効、5σ は検討例です。天体自体のクリッピングや最終光度曲線の後処理とは別です。
- **Save per-star flux cube** は本測光後、全開口・全天体のフラックスと誤差を別の `*_flux_datacube.npz` として保存します。大きくなる場合があり、再処理には prose2 を使います。

v3.8.0 の本測光は各バンドの予測ノイズをログと主 NPZ に保存します。画面では光子、空、読み出し、比較星、合計予測ノイズと、実測した隣接点間の散らばり（ppt）、および両者の比を確認できます。欠測や非有限値は利用不可、旧結果に診断値がなければ表は表示されません。値は測光時の診断結果であり、後処理後の再計算やトランジットフィットの誤差推定ではありません。

#445 の精度向上は、暗い天体をデフォーカスで観測した一晩の測定結果です。設定を比較する際は別の実行名を使ってください。FWHM に応じた背景環は **Aperture & Geometry** の手動設定で、開口半径と背景環は選択した同じ単位で指定します。

## 検証、再現性、計算環境

pytest で単体・統合テストを実施し、実データで全パイプラインを動かす試験には `@pytest.mark.slow` を使います。光度曲線、FWHM・エアマス・重心との相関、残差、コーナープロット、トレースを matplotlib や Plotly で確認します。暦表・可視性は NASA Exoplanet Archive などと照合し、フィットは他のコードとも比較します。

各実行の `meta.yaml` に本体・エンジンのバージョン、設定、実行パラメーターを記録します。観測メタデータの整合性にはデータベースの制約を使います。Python 3.12 以降、astropy（FITS、WCS、座標、時刻）、NumPy、SciPy、astroquery を利用します。prose.SequenceParallel が測光を並列化します。解析エンジンは独立して版管理され、muscat-db が専用環境でサブプロセスとして起動して出力を追跡します。環境管理には uv と conda を使います。

## 今後の研究・開発

GPU を使った高速化（Numba/CUDA、CuPy）、より高度なガウス過程や機械学習による系統誤差補正、観測ログからの惑星自動探索、装置間の較正、TIC・Kepler・K2 等との連携拡大、相互作用の強い系の N 体 TTV モデルは調査・計画段階です。

## 視野表示と外部サービスの障害

FOV フォームは天球ビューアーから独立しています。CDS から Aladin Lite 3.8.1 を非同期で読み込み、初期化に失敗するか 8 秒を超えると **Sky view unavailable (CDS unreachable)** と表示します。**Resolve** と **Run** は利用でき、時間内に初期化すれば先に取得した結果も描画します。サーベイ画像の表示には CDS が必要です。

Gaia の円錐検索は ESA の同期 TAP、次に VizieR を使い、各サービスの通信無応答タイムアウトは 5 秒です。成功結果を探索円と等級範囲でメモリ・ディスクにキャッシュし、失敗時はすぐ再試行できます。これは最適化全体の制限時間ではありません。

**Resolve** と名前だけを指定した **Run** は `catalog.resolve_target_astrometry()` で NASA/TOI、Sesame、ExoFOP の順に調べます。座標を指定すれば名前解決は不要です。Sesame（Harvard ミラーを含む）と ExoFOP は各 5 秒の無応答でタイムアウトします。Sesame は通信障害後の表記違いの再試行を止め、失敗結果を 30 秒保持します。ExoFOP 成功結果はアーカイブ検索と容量制限付きで 1 時間共有します。座標の出典は exofop とし、元期・固有運動は不明として扱います。

予約・暦表・アーカイブにもこの座標解決を使います。天体ページはローカルカタログを照合した後に座標解決を行い、最後の手段としてヘッダーの指向中心を使います。露出計算の Sesame 検索・等級取得と測光エンジンの名前解決はそれぞれ独立しています。
